Part 1: Data Joins

Intro to different types of joins

Let’s say you have multiple hierarchies of data and you want to join them into one big data set. Join functions are the way you would do it.

Data 1

Site_number Treatment Nitrate Temp
1 High 1.2 7.2
2 High 3.0 7.8
3 Low 2.4 8.0
4 Low 5.1 8.0
5 Low 1.1 7.9

Data 2

Site_Number Sample_number Biomass
1 1 12.2
1 2 14.0
1 3 11.9
1 4 10.0

Identifying the key

Which column is consistent across both datasets?

Data 1

Site_Number Treatment Nitrate Temp
1 High 1.2 7.2
2 High 3.0 7.8
3 Low 2.4 8.0
4 Low 5.1 8.0
5 Low 1.1 7.9

Data 2

Site_Number Sample_number Biomass
1 1 12.2
1 2 14.0
1 3 11.9
1 4 10.0

The column name must be identical in both dataframes (spelling, capitalization, everything). This is your key.

Whenever collecting data, include a unique ID for every sample. This makes joining datasets much easier!

Creating sample tibbles

Let’s create two small example datasets:

T1 <- tibble(
  Site.ID = c("A", "B", "C", "D"),
  Temperature = c(14.1, 16.7, 15.3, 12.8)
)

T1
# A tibble: 4 × 2
  Site.ID Temperature
  <chr>         <dbl>
1 A              14.1
2 B              16.7
3 C              15.3
4 D              12.8

Creating sample tibbles (continued)

Now create a second tibble:

T2 <- tibble(
  Site.ID = c("A", "B", "D", "E"),
  pH = c(7.3, 7.8, 8.1, 7.9)
)

T2
# A tibble: 4 × 2
  Site.ID    pH
  <chr>   <dbl>
1 A         7.3
2 B         7.8
3 D         8.1
4 E         7.9

left_join()

left_join() keeps all rows from the left (first) dataframe and adds matching rows from the right:

left_join(T1, T2)
# A tibble: 4 × 3
  Site.ID Temperature    pH
  <chr>         <dbl> <dbl>
1 A              14.1   7.3
2 B              16.7   7.8
3 C              15.3  NA  
4 D              12.8   8.1

Notice that Site “C” stays (from T1) but “E” is excluded (only in T2).

right_join()

right_join() keeps all rows from the right (second) dataframe:

right_join(T1, T2)
# A tibble: 4 × 3
  Site.ID Temperature    pH
  <chr>         <dbl> <dbl>
1 A              14.1   7.3
2 B              16.7   7.8
3 D              12.8   8.1
4 E              NA     7.9

Now Site “E” is included, but “C” is excluded.

inner_join()

inner_join() keeps only rows that exist in both dataframes:

inner_join(T1, T2)
# A tibble: 3 × 3
  Site.ID Temperature    pH
  <chr>         <dbl> <dbl>
1 A              14.1   7.3
2 B              16.7   7.8
3 D              12.8   8.1

Only sites A, B, and D are kept. C and E are dropped.

Data loss risk

inner_join() drops unmatched rows. Always check your result to ensure you haven’t unexpectedly lost data.

full_join()

full_join() keeps all rows from both dataframes:

full_join(T1, T2)
# A tibble: 5 × 3
  Site.ID Temperature    pH
  <chr>         <dbl> <dbl>
1 A              14.1   7.3
2 B              16.7   7.8
3 C              15.3  NA  
4 D              12.8   8.1
5 E              NA     7.9

All sites (A, B, C, D, E) are kept, with NA filling in missing values.

semi_join()

semi_join() keeps rows from the first dataframe where there are matches in the second, but only returns columns from the first:

semi_join(T1, T2)
# A tibble: 3 × 2
  Site.ID Temperature
  <chr>         <dbl>
1 A              14.1
2 B              16.7
3 D              12.8

Only sites A, B, D from T1, and only the Temperature column (from T1).

anti_join()

anti_join() returns rows in the first dataframe that do not match the second:

anti_join(T1, T2)
# A tibble: 1 × 2
  Site.ID Temperature
  <chr>         <dbl>
1 C              15.3

Only Site C from T1 is returned (it has no match in T2).

Finding missing data

Use anti_join() to identify unmatched records and detect data quality issues.

Summary of join types

Join Keeps Use when
left_join() All left rows + matches Primary dataset is on the left
right_join() All right rows + matches Primary dataset is on the right
inner_join() Only complete matches Need only complete pairs
full_join() All rows from both Want to keep everything
semi_join() Left rows with matches Filtering without duplication
anti_join() Left rows without matches Finding unmatched data

Common gotcha: Joining by different column names

What if your tables use different column names for the same information?

T3 <- tibble(
  SiteID = c("A", "B", "C", "D"),  # Note: different name!
  Chlorophyll = c(2.3, 3.1, 1.9, 2.8)
)

T3
# A tibble: 4 × 2
  SiteID Chlorophyll
  <chr>        <dbl>
1 A              2.3
2 B              3.1
3 C              1.9
4 D              2.8

Notice T1 uses Site.ID but T3 uses SiteID. These are the same thing!

Joining with by argument — Different column names

Use the by argument to specify column mapping as a named character vector:

left_join(T1, T3, by = c("Site.ID" = "SiteID"))
# A tibble: 4 × 3
  Site.ID Temperature Chlorophyll
  <chr>         <dbl>       <dbl>
1 A              14.1         2.3
2 B              16.7         3.1
3 C              15.3         1.9
4 D              12.8         2.8

The syntax is: by = c("left_table_col" = "right_table_col")

This is one of the most common mistakes students make — don’t forget the by argument!

Joining by multiple columns

When matching requires multiple columns, specify all of them:

T4 <- tibble(
  Site.ID = c("A", "A", "B", "B"),
  Year = c(2020, 2021, 2020, 2021),
  Biomass = c(12.5, 15.3, 18.2, 16.9)
)

T5 <- tibble(
  SiteID = c("A", "A", "B"),
  Year = c(2020, 2021, 2021),
  Nutrients = c(8.2, 7.9, 9.1)
)

left_join(T4, T5, by = c("Site.ID" = "SiteID", "Year" = "Year"))
# A tibble: 4 × 4
  Site.ID  Year Biomass Nutrients
  <chr>   <dbl>   <dbl>     <dbl>
1 A        2020    12.5       8.2
2 A        2021    15.3       7.9
3 B        2020    18.2      NA  
4 B        2021    16.9       9.1

Notice Year appears in both with the same name. You must still include it in the by argument when joining by multiple columns.

Handling naming conflicts: .x and .y suffixes

What happens when both tables have columns with the same name but you’re NOT joining by them?

T6 <- tibble(
  Site.ID = c("A", "B", "C"),
  Notes = c("pristine", "degraded", "moderately impaired")
)

T7 <- tibble(
  Site.ID = c("A", "B", "D"),
  Notes = c("sunny", "shaded", "partially shaded"),
  Quality = c("good", "fair", "poor")
)

# Don't specify how to join — creates ambiguity with 'Notes'
left_join(T6, T7, by = "Site.ID")
# A tibble: 3 × 4
  Site.ID Notes.x             Notes.y Quality
  <chr>   <chr>               <chr>   <chr>  
1 A       pristine            sunny   good   
2 B       degraded            shaded  fair   
3 C       moderately impaired <NA>    <NA>

See the .x and .y suffixes on Notes? They distinguish which table each column came from!

Avoiding naming conflicts

Best practice: rename columns before joining to avoid confusion

T6_renamed <- T6 |> 
  rename(Condition_Notes = Notes)

T7_renamed <- T7 |> 
  rename(Habitat_Notes = Notes)

left_join(T6_renamed, T7_renamed, by = "Site.ID")
# A tibble: 3 × 4
  Site.ID Condition_Notes     Habitat_Notes Quality
  <chr>   <chr>               <chr>         <chr>  
1 A       pristine            sunny         good   
2 B       degraded            shaded        fair   
3 C       moderately impaired <NA>          <NA>

Much cleaner! No .x and .y suffixes, and the data is self-documenting.

Timezone awareness: A real-world challenge

Your data may come from different timezones, or your system timezone may differ from data collection timezone. This causes major problems if you ignore it!

Example: Data collected in Hawaii (HST) but your computer is in EST.

# Create a datetime WITHOUT timezone info
datetime_naive <- mdy_hms("02/24/2021 10:22:20")
datetime_naive
[1] "2021-02-24 10:22:20 UTC"

This object has NO timezone information — dangerous!

with_tz() — View same moment in different timezone

Use with_tz() to interpret the same clock time in a different timezone:

# Assume the naive time is in Hawaii
hawaii_time <- with_tz(datetime_naive, tzone = "US/Hawaii")
hawaii_time
[1] "2021-02-24 00:22:20 HST"
# Same moment, viewed from EST
est_time <- with_tz(hawaii_time, tzone = "EST")
est_time
[1] "2021-02-24 05:22:20 EST"

The instant in time is the same; we’re just viewing it in different timezones. Notice the hour changed!

force_tz() — Change the timezone label

Use force_tz() to reassign a naive datetime to a specific timezone (claim it was collected there):

# Claim this was collected in Hawaii (though it was naive)
force_hawaii <- force_tz(datetime_naive, tzone = "US/Hawaii")
force_hawaii
[1] "2021-02-24 10:22:20 HST"
# Now convert to EST (this changes the clock time!)
with_tz(force_hawaii, tzone = "EST")
[1] "2021-02-24 15:22:20 EST"

Important: force_tz() changes the clock reading because you’re assigning timezone info to a previously naive datetime.

with_tz() vs force_tz() — Key difference

Function Use when Effect
with_tz() Datetime HAS timezone; you want to view it in a different one Clock changes, instant stays the same
force_tz() Datetime is NAIVE; you want to claim where it was collected Instant changes, timezone label added

This confuses everyone!

A common mistake: using with_tz() when you meant force_tz(), or vice versa. Always verify your datetime after conversion!
