Quarto Cheatsheet

Working with figures

We can change lots of aspects of the figure right in our markdown document:

  • change size
  • change resolution
  • change “device” (i.e. is it a .png, .pdf, etc.)
  • save it to a specific folder

Start a Quarto document

  • Open a new .qmd file and set it up
  • Load the appropriate libraries and make a very simple plot with the penguin package of anything (don’t overthink it this is just for practice)

Change the size of a figure

Some options:

  • out-width: "70%" (makes it 70% of the width)
  • fig-width: 3 (make the width 3 inches)
  • fig-height: 4 (make the width 4 inches)
  • fig-align: "center" (center aligns the figure)

We will walk through each of these together. See here for all options

Label a figure

We can add labels to figures and captions and subcaptions.

Some options:

  • label: some-fig-lab (allows you to call the figure in your quarto file and it automatically give it a number)
  • fig-cap: "my caption" (gives your figure a caption)

Automatically save all your figures in your output folder

This will automatically save every figure in your output folder with the fig size based on your YAML and named with the label you gave it. NOTE Quarto automatically saves everything to the file location NOT the project location

knitr:
  opts_chunk:
    fig.path: "../output/" ## added the ../ because your qmd folder is in your scripts folder so we need to go up one directory and then into your output folder

Tables with kableExtra

install.packages("kableExtra")
penguins |>
  group_by(species) |>
  summarise(billmean = mean(bill_length_mm, na.rm = TRUE)) |>
  kbl() # make it a kable table

Note You can add a label to this code chunk too just like your figure and reference your table in the text by using tbl-name in your label.

Add some style

penguins |>
  group_by(species) |>
  summarise(billmean = mean(bill_length_mm, na.rm = TRUE)) |>
  kbl()  |> # make it a kable table
  kable_classic() |> # add a theme

Cross-references

Cross-references: figures

One of Quarto’s biggest advantages for scientific writing: figures and tables are auto-numbered and linkable from your prose.

Step 1: Give your chunk a label starting with fig-

#| label: fig-penguin-bill
#| fig-cap: "Bill length vs. bill depth for three penguin species."
#| echo: false

ggplot(penguins, aes(x = bill_depth_mm, y = bill_length_mm, color = species)) +
  geom_point() +
  scale_color_viridis_d()

Step 2: Reference it anywhere in your prose with @fig-penguin-bill

As shown in @fig-penguin-bill, bill dimensions differ clearly by species.

Renders as: “As shown in Figure 1, bill dimensions differ clearly by species.” — auto-numbered!

Cross-references: tables

Same pattern for tables — label must start with tbl-

#| label: tbl-penguin-means
#| tbl-cap: "Mean bill length by species."

penguins |>
  group_by(species) |>
  summarise(mean_bill = mean(bill_length_mm, na.rm = TRUE)) |>
  kbl()

Then in your prose:

Mean bill lengths are summarised in @tbl-penguin-means.

Renders as: “Mean bill lengths are summarised in Table 1.”

Prefix rules

  • Figures must use a fig- prefix — label: fig-my-plot
  • Tables must use a tbl- prefix — label: tbl-my-table
  • Quarto will error if the prefix doesn’t match the cross-reference type

Activity: Cross-references

In your Quarto document:

  1. Create a code chunk that makes a ggplot — give it a fig- label and a fig-cap:
  2. Create a code chunk that makes a kbl() table — give it a tbl- label and a tbl-cap:
  3. In a prose paragraph, reference both with @fig-... and @tbl-...
  4. Render and confirm Figure 1 and Table 1 appear as clickable cross-links

Most common mistake

Missing or wrong prefix — if the cross-reference isn’t rendering, check that the chunk label starts with exactly fig- or tbl-.

code-fold — show/hide code in your output

One line of YAML lets readers toggle code on and off without changing echo::

---
title: "My Analysis"
format:
  html:
    code-fold: true              # code hidden by default, with a toggle button
    code-summary: "Show code"    # customize the button label
---

When to use each approach

Option Best for
echo: false Reports where readers never need to see code
code-fold: true Reports where code is optional — reviewers, collaborators
echo: true (default) Teaching materials, methods sections, reproducible workflows

Outputs

There are also many different formats. Here is a list of different documents. I really like GitHub documents because you can view them right in GitHub! PDF is also very useful.

Note you cannot use html interactive files in a gfm document. You will need to install the webshot2 package which automatically turns them into screenshots if you have an html table, for example, in your file.
